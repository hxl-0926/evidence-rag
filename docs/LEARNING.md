# 从跑通到能讲清楚

## 第一次：20 分钟

运行 README 的两条命令，分别问“主动回忆”“SQLite transaction”和完全不存在的关键词。观察分数、行号与拒答。打开源笔记，对照实际行号验证输出。不要把 BM25 分数当成概率。

## 第二次：30 分钟

读 `src/search.mjs`。手算两个短文档的词项频率和 DF，修改 `k1`、`b` 再比较排序。尝试只保留中文单字，观察短语命中与噪声。测试一个没有词项交集但语义相近的问题，解释词法检索的局限。

## 第三次：40 分钟

读 `src/answer.mjs`。用测试中的假 HTTP 响应返回不存在的引用，确认程序拒绝输出。再返回一个真实 ID 但错误的事实，理解“引用 ID 合法”与“事实有依据”的区别。

## 值得自己完成的扩展

1. 做 30 个标注问题，按知识点分组留出测试集，避免边看测试集边调参。
2. 将结果转换成 rag-bench 的 JSONL，统一使用来源文件作为文档 ID；若评测片段，须固定分块版本和 ID。
3. 增加倒排表，只累加查询词项对应片段的分数，并与现实现做结果一致性测试。
4. 接入向量检索，比较纯 BM25、纯向量和 RRF 融合；先记录质量与延迟再判断是否值得。

能讲清楚的问题：为什么高频词的区分度更小？为什么要归一化文档长度？什么情况下检索到了资料仍应拒答？重建索引为什么会让某些引用 ID 改变？
